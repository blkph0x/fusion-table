The launcher selects a compatible installed Node >=22.13 for its own process.
It now selects the conventional Node runtime by default so shared cook reports
and recorded prices use a real persistent filesystem. The original Worker
profile remains available explicitly with -Runtime worker. Bare package scripts
and the managed Sites build keep their Worker default.
It avoids the default shell's older Node and failing global pnpm launcher.
It does not change global Node, pnpm, PATH or execution-policy settings.
NEXT_PUBLIC_BASE_PATH is selected for that invocation and restored afterward.
The checked-in configuration now supports this environment variable, eliminating
the need to hard-code host-only path edits in a local preview.

Other tasks:
  powershell -NoProfile -File scripts/Start-Fusion.ps1 -Task status
  powershell -NoProfile -File scripts/Start-Fusion.ps1 -Task build
  powershell -NoProfile -File scripts/Start-Fusion.ps1 -Task start
  powershell -NoProfile -File scripts/Start-Fusion.ps1 -Task verify
  .\scripts\Start-Fusion.ps1 -BasePath ''

An empty BasePath preserves the normal portable root-path build. The /fusion
profile matches paths, not every host service: the server's optional local image
model is not installed or configured by this launcher. Android downloads on the
live domain are served separately by Apache at /downloads, not inside /fusion.
A local web-only preview does not contain that separately hosted APK by default.

Node self-hosting (Linux shell with the required Node/pnpm already selected):
  FUSION_RUNTIME=node NEXT_PUBLIC_BASE_PATH=/fusion pnpm build
  FUSION_RUNTIME=node NEXT_PUBLIC_BASE_PATH=/fusion FUSION_DATA_DIR=/persistent/fusion-data node scripts/run-framework.mjs start --port 8792
Use one supervised Node writer process for this JSON ledger, and back up its
FUSION_DATA_DIR. A Worker --persist-to directory does not make arbitrary node:fs
writes durable; this was confirmed by failing local Worker writes. Node dev and
production writes were tested across independent requests and a full restart.
Use a separate storage adapter before scaling this ledger across processes.
Worker and Node builds share dist, so build the intended profile before starting;
the launcher detects an incompatible build instead of silently starting it.

Image rendering can be bounded with FUSION_LOCAL_IMAGE_CONCURRENCY (1-4, default2)
and FUSION_LOCAL_IMAGE_TIMEOUT_MS (1000-60000, default20000). Render/cache behaviour
does not establish that a recipe was cooked or photographed.
For the Node profile, supply FUSION_LOCAL_IMAGE_URL explicitly with the existing
host model's loopback endpoint if wanted. Node does not automatically read the
Worker .dev.vars file. Without a model endpoint, the image fallback still works.
