# Fusion Table v0.2.0 — deterministic barbecue and ingredient-led meals

The recipe system uses authored templates only. Identical selections produce identical output, with no runtime language model, paid generation service or random recipe generation.

## Expanded classic studio

- 20 new barbecue/smoking classics, retaining all 8 originals: **28 classics** in total.
- 16 new regional profiles, retaining all 8 originals: **24 regions** in total.
- All 5 dietary preferences remain supported: **672 classic/region pairings** and **3,360 classic/region/diet configurations**.
- New recipes cover brisket, pulled protein, ribs, sausages, skewers, reverse-seared and flank steaks, lamb chops, wings, whole chicken, turkey breast, pork belly, hot-smoked/whole fish, prawns, ready-cooked octopus, vegetable trays, grain bowls, smoked dip and ready-to-eat cold platters.
- Technique notes distinguish outdoor smoking, direct/indirect grilling and ordinary kitchen alternatives. Smoking wood is not a required shopping ingredient.
- Cold platters use commercially ready-to-eat products or fully cooked alternatives. No home raw-fish curing or raw-fish cold-smoking shortcut is included.

The [README catalog tables](https://github.com/blkph0x/fusion-table/blob/v0.2.0/README.md) summarize every new classic and profile.

## Ingredient-led meals and shopping

The additional meal builder retains 22 mains, 12 supported techniques, 20 regional profiles and 6 side combinations: **23,400 compatible main/method/region/side configurations**. It preserves the selected main and rejects incompatible dietary/method choices. These counts describe template configurations, not independently kitchen-tested recipes.

All recipes carry the exact label **“Template-generated · not kitchen-tested”**. Servings, heat, pantry matching, cooking mode, notes, ratings, exports and nearby food-shop suggestions remain available. New cookbook saves are limited to 100; existing entries are retained.

## Download and use

- **Source ZIP:** complete tracked source, recipe catalogs, image assets, server routes, tests, documentation, build helpers and pnpm lockfile. Extract it, then run `pnpm install --frozen-lockfile`, `pnpm dev` or `pnpm build`.
- **Cloudflare Worker archive:** compiled server/client assets and deployment instructions. Use your own Cloudflare account and explicit Worker name; no Sites project manifest or local environment files are included.
- **SHA256SUMS:** checksums for both release archives.

Use Node.js 22.13.0+ and pnpm 11.25.0. Recipe generation works without credentials or network calls. Live location/shop searches need server routes and internet access; static GitHub Pages hosting alone is insufficient. **Access correction:** the GitHub repository and published release downloads are public. The existing hosted Sites app remains owner-private.

Automated checks cover the full classic/region/diet matrix, dietary substitutions, selected cuts, temperature endpoints, ready-to-eat handling, deterministic output, pantry safeguards and source/build portability. They do not establish taste, a completed kitchen trial, or retailer stock/prices. Cookbook data remains browser-local.
