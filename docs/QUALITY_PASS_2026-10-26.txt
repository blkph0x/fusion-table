Recipe correctness fixes

- Complete-plate diet, allergen and dislike checks now apply to unseeded meals
  and classic presets as well as seeded variations. Exclusions are not relaxed.
- Explicit vegan/vegetarian constraints reject incompatible animal mains.
- Oyster sauce records mollusc as an allergen; supported aliases are normalised.
- Corrected 57 citrus quantities and three dairy-free variants, and removed two
  unfinished quantity placeholders in sides.
- Cleaner settings retain authored quantities, so method amounts agree with the
  ingredient list. The vegetable setting prefers vegetable-rich sides instead
  of silently rewriting quantities after steps have been written.
- Ingredient-led meals keep their selected side; rice/salad no longer silently
  gains extra bread, potatoes or grains. Regional rice names, packet directions
  and final serving instructions agree. Classic authored staple choices remain.
- Specified vegan garlic bread/kimchi and a gluten-free oat-side alternative.
- Smoking instructions retain the full cooking stage and doneness checks.
- Cleaner sauces are described from retained ingredients, avoiding names such as
  coconut sauce after coconut milk was removed.
- Broth finishes require an appropriate curry/braise and sufficient measured
  retained cooking liquid. Dry grilled plates cannot become a nominal broth bowl.
- Transformed meals complete final assembly/chilling before serving. Earlier
  cooking endpoints remain. Chilling time is explicitly additional.
- Classic regional staples now include scaled preparation directions before
  service; merely renamed existing rice is not cooked twice. Both classic and
  ingredient variations defer serving until final assembly. Prawn additions are
  cooked through and chilled before cold assembly, and finished-dish wording
  calls them cooked. Fish sauce does not trigger a nonexistent fish-cooking step.

Recipe identity, recovery and shopping fixes

- Generated recipes retain their cooking inputs. Links and PDFs keep cuts,
  cleaner preferences, constraints, seed, session and weekly flavour choices.
- Sharing/PDF controls check that rebuilding still matches actual cooking
  content. Older snapshots that no longer reproduce keep JSON download rather
  than silently sharing a changed recipe.
- Stored recipe identity includes cooking content, preventing two differing
  recipes with the same old template ID from overwriting each other's notes.
- Recipe images are derived from the verified snapshot, rather than trusting a
  potentially unrelated imported token. Static meal inspiration images also
  require the matching side.
- Cookbook JSON import validates the whole file before changing anything,
  merges without duplicate cooking snapshots, and preserves existing feedback.
  Corrupt optional fields and hidden/inconsistent allergen summaries are rejected.
- Active notes/rating forms stay in sync with imported/saved feedback. A zero
  rating is retained. Opening a planned recipe clears unrelated prior notes.
- Shopping preparation preserves pantry stock. 'Finished cooking' consumes once
  per mounted recipe, with Undo; later external stock edits prevent unsafe undo.
- Exact g/kg and ml/l conversions work; no spoon/density conversions are guessed.
- Shopping uses current pantry stock/notes instead of stale imported ownership
  flags. Lists retain their origin label rather than borrowing a newer meal title.

- Cook-report quantity changes are explicit previews; they no longer replace

- Every displayed allergen exclusion is accepted by the weekly planner. Its

Performance and backend reliability

- Three inspiration PNGs total 9,449,533 bytes. Their 960px WebP versions total
  570,102 bytes (94% smaller); 480px thumbnails total 169,578 bytes. Originals
  are retained. Cards use responsive sizes, and matching static API images use WebP.
- Week side alternatives are memoised instead of regenerated on unrelated renders.
- Image requests coalesce by token. Cache is limited to 40 entries/24MB; two full
  renders run concurrently by default. Excess work gets a short-lived fallback.
  Configured-model failures can recover after five seconds, with a default
  20-second model deadline rather than four minutes. Tests use fake renderers.
- Confirmed Worker-preview community/price writes returned 503. The explicit
  self-hosted Node profile fixes this with real filesystem storage.
- Node dev and production report/price writes survived independent requests and
  complete server restarts. Tests used isolated synthetic local ledgers only.
- Ledger writes are atomic, byte-bounded and fail without deleting corrupt
  existing data. Request bodies, request time, identifiers and rate-memory growth
  are bounded. One supervised Node writer is required for the JSON ledger.

Limits and deployment boundary

These tests establish declared structure, constraints, consistency and working
flows. They do not establish taste, kitchen repeatability, allergen-free packaged
products, retailer shelf stock or a production performance score. Full screen-
reader/device testing remains separate from these browser/layout checks.

The full 76-region cross-product is not claimed to have been exhaustively cooked
or tested: all 76 profiles have coverage, while the 668,430-case exhaustive run
uses seven representative regions. The Android companion was outside this
website implementation pass. Classic multi-staple plates retain their existing
authored behaviour, and pantry cook Undo lasts until leaving/reloading the recipe.
Input-only share links rebuild with the current recipe rules. They are not an
immutable archive across later generator releases; cookbook JSON retains the
written snapshot, and saved recipes that no longer reproduce do not offer a
misleading regenerated share/PDF from the planner.

Deploy the Node profile with persistent data and the existing local image model's
loopback environment setting if that model is wanted on the host. Worker and
Node builds are different outputs. The live server is unchanged until a deliberate
deployment; a tested local build alone does not update gearsqueens.online.
